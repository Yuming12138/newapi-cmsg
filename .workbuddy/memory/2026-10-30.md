
## cli2api 升级 v0.7.25（面板自动更新首次跑通）
- 面板报错 `download host updater ... unexpected EOF` 的残留：updater 的 status.json 里存着旧失败 job（agent.current_version=v0.7.13, state=failed）。删 /var/lib/cli2api-updater/status.json 后重启 updater 即恢复 idle。**教训：status.json 会留历史 job，面板优先渲染 agent 段，仅核对 current_version 会漏判。**
- 用户手动点「下载更新」→ updater 拉到了 v0.7.25 镜像、做了 DB 快照（/opt/cli2api/data/backups/qoder-20261030T081217.754314261Z.db），但**健康检查失败并自动回滚**：`health check did not reach version v0.7.25`。
- 根因：10-29 我把 compose 的 image 从 `:latest` 改成固定 `:v0.7.20`。updater 只 pull + 重建，**不改 compose tag**，重建后仍跑 v0.7.20 → 版本校验失败 → 自动回滚（保护机制本身是对的）。
- 修复：compose 改回 `:latest`（远端 latest digest == v0.7.25，即 44a28d14a6e8），手动 up -d 完成升级。DEVELOPMENT.md 里"tag 要固定版本"那条已改成"必须保持 :latest"并写明原因。

- 已知小瑕疵：agent.version 仍显示 v0.7.20（updater 缓存，不影响 current_version 与面板主显示）。
- 面板现已无可用更新（next_version=None, has_update=False, state=idle）。
