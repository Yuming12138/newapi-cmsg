## 根因确认并修复：渠道 1/27 的坏代理（已恢复 asxs 主力）
- **根因**：`channels.setting`（注意不是 `settings` 列！）里给渠道 1/27 配了 `"proxy":"http://mihomo:7890"`。
  mihomo 的 7890 代理当前不健康（宿主 `curl -x 127.0.0.1:7890` 返回 000），
  导致 New API 走该代理时 CONNECT 后立刻被关 → `do request failed: ... EOF`。
  之前一直没查到，是因为只 grep 了 `settings` 列，`setting` 列才是 ChannelSetting.Proxy 的来源。
- **定位手段**（可复用）：commit `d4886cf` 加了 `CMSG_FORCE_DIRECT=true` 开关（强制忽略环境/渠道代理）+ 在 `doRequest` 打印运行时 `info.ChannelSetting.Proxy`。
  日志直接输出 `channel=1 proxy="http://mihomo:7890"`，一次命中。开关保留在代码里（默认 false），可作应急。
- **最终修复**（未依赖开关）：`UPDATE channels SET setting=(setting::jsonb - 'proxy')::text WHERE id IN (1,27)`；
  compose 里 `CMSG_FORCE_DIRECT: "false"`，重建容器。
- **其他变更**：按用户要求把 1/27 的 base_url 从 `https://api.itygk.sbs` 换成 **`https://api.hfjtc.cfd`**（不能带 /v1，GetFullRequestURL 会拼 /v1/...）。新域名宿主直连 2-3s，旧域名已劣化到 10-28s。
- **验证**：撤掉开关后渠道 27 测试 success:true 1.9s；恢复 `cmsg_peak_shift.py off` + 启动 timer 后，
  3 次 `/v1/responses` 全 200 且全部走**渠道 1**（asxs 主力恢复）。ttfb 19-30s 仍偏慢（上游自身响应慢）。
- 排查中已排除：上游服务、DNS/IPv6、HTTP/1.1 vs 2、容器环境变量代理、RELAY_TIMEOUT=0、SSRF、全局 httpClient 改写、重启。
  决定性实验：同容器同网络独立 Go 客户端 8/8 全 200，而 New API 进程所有外部 HTTPS 全 EOF → 锁定进程内渠道级 proxy。
- 待清理：compose 的 `extra_hosts: api.itygk.sbs:172.67.187.236` 已无用了（域名已换），可删。
- 注：mihomo 与 new-api 在**同一** docker 网络（`getent hosts mihomo` → 172.18.0.6），allow-lan=true/bind 0.0.0.0，
  所以代理失效不是网络隔离，是 7890 代理本身/节点不健康；换订阅地址理论上能修，但直连已可用，未采纳。

## 让 api.asxs.top 在服务器可达：根因=SNI 封锁，四组代理方案均失败
- 精确定位：TCP 443 到 CF IP **OPEN**；`curl -v --resolve` 显示 TLS Client Hello 后
  `Connection reset by peer` → **按 SNI=api.asxs.top 阻断**，不是 DNS 也不是端口不通。
  DoH 三个 A 记录 104.26.8.239 / 104.26.9.239 / 172.67.69.238 全部同样 RST，换 IP/hosts 无效。
- 服务器侧代理穷举（对照组 hfjtc.cfd 均 401/200 证明代理本身工作）：
  1) proxyinfo 新订阅 12 节点 + 最小配置 → asxs 000
  2) 同上 + `hosts` 固定正确 CF IP → asxs 000
  3) 用户当前 Clash profile 19 节点 + 最小配置 → asxs 000
  4) 同上 + profile 的 fake-ip DNS 段 → 连 hfjtc 也 000（DNS 段拖垮）
  5) 用户完整 profile 原样 → 全部 000
  结论：用户本机 Clash 能通（首页200/billing 401），但该路径在阿里云出口无法复现，疑与本机 TUN/系统代理或家宽网络环境有关。
- 理论可行但未做：ECH(Encrypted Client Hello) / TLS 分片 / 抗封锁隧道，成本高于收益。
- **重要：余额已改走 /api/usage（见上条），api.asxs.top 不可达不再阻塞任何功能**，不建议继续投入。
