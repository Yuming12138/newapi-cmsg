
## cli2api 升级 v0.7.20 + 宿主更新器 + 全链路代理
- 原故障：面板更新报 `download host updater: Get "https://github.com/caigee-cmd/cli2api/releases/download/v0.7.20/cli2api-updater_linux_amd64": unexpected EOF`。
  双重原因：① cmsg 直连 github.com 完全超时（实测 10s → 000）② 宿主更新器从未安装（/run/cli2api-updater 空目录 + 容器 ro 挂载），面板按钮缺依赖。
- 版本升级：compose `/opt/cli2api/deploy/docker-compose.yml` 由 `:latest`(旧, 2天前, v0.7.13) 改为固定 `:v0.7.20`（镜像本地早已存在）。up -d 重建后 /health= v0.7.20 commit af5f3c0。
  - 兼容性验证：/api/accounts 结构不变（accounts 11→17，ready=14，credits=9973）；余额同步脚本正常；New API 手动刷 ch36 = 9973；真实请求 200 ttfb 0.9s。
  - 新版本两个 qoder 账号 status=error（不再计入额度池）。
- 更新器安装：`sudo env HTTP_PROXY/HTTPS_PROXY=http://127.0.0.1:7897 ./deploy/install-updater.sh`（代理必须加，否则 checksum/release 下载失败）。
  产物：/usr/local/bin/cli2api-updater、systemd `cli2api-updater.service`(enabled)、socket /run/cli2api-updater/updater.sock、status /var/lib/cli2api-updater/status.json。
  注意：status.json 里会残留安装前的失败记录（current_version 显示旧值），以 `/api/system/update` 实时返回为准。
- 代理配置（两层，都必须）：
  1. updater：/etc/systemd/system/cli2api-updater.service.d/proxy.conf（HTTP(S)_PROXY=7897，NO_PROXY 本地）
  2. dockerd：/etc/systemd/system/docker.service.d/http-proxy.conf（同上 + 容器名 NO_PROXY）。**必须 systemctl restart docker**，期间 6 个容器全部重启约 30-60s；重启后 mihomo 容器自动回来，7897（docker-proxy 映射）随之恢复，无循环依赖。
  - 验证代理生效方法：`docker pull ghcr.io/caigee-cmd/cli2api:v9.9.9` 应返回 **not found**（而非超时）。
- 最终验证：`/api/system/update` 返回 current_version=v0.7.20 + rollback_versions(v0.7.19...)，面板可正常检查更新/回滚。
- 代理端口备忘：cmsg 上 127.0.0.1:7897 是 mihomo 容器的 docker-proxy 映射（同容器还映射 7890/1080）。
- 镜像保留：latest(旧) / v0.7.19(回滚用) / v0.7.20(当前)，各 ~240MB 实占。
