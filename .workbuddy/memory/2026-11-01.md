
## cli2api v0.7.25 → v0.7.26：面板更新根本性缺陷 + 更新脚本
- 用户 11-01 02:10 点面板更新，卡 13.7 小时（面板计时 49395s）才被今天 15:52 的新 job 取代；今天那次 2 分钟内失败回滚：
  `update failed and was rolled back: health check did not reach version v0.7.26`。
- **根因（updater 设计缺陷，非配置问题）**：updater 按目标版本拉镜像 `docker pull repo:v0.7.26`，而 compose 用 `repo:latest` 重建。拉版本 tag **不会移动本地 :latest**（本地 latest 仍是 v0.7.25 的 44a28d），所以重建后跑回旧镜像，版本化健康检查失败 → 自动回滚。
  之前把 compose 固定成 `v0.7.20` 也失败，是同一矛盾的另一面：两种 tag 写法都不行。
- 昨晚卡 13h 的原因：卡在镜像下载阶段（762MB 走代理），updater 的 `-health-timeout 2m` 只覆盖重建后的健康检查，不覆盖下载阶段，所以没有超时兜底。
- 临时解法（已验证）：`docker pull repo:latest`（远端 latest 已指向新版本 digest）→ `docker compose up -d`。本次即用此法从 v0.7.25 升到 v0.7.26（commit 10bff72625e8）。
- 持久解法：新增 `/opt/scripts/update-cli2api.sh`
  - 用法：`sudo /opt/scripts/update-cli2api.sh`（到 latest）或 `... v0.7.26`
  - 逻辑：pull → 非 latest 时 docker tag 对齐 latest → up -d → 轮询 healthy+版本校验（最多 2min）→ 失败自动把 latest 指回上一 image_id 重建回滚
- v0.7.26 验证：/health version=v0.7.26 ok=true；余额脚本 ready=17 credits=14315；渠道36 刷新 14315；真实请求 200 ttfb 1.16s。
- 面板现状：current=v0.7.26 / has_update=False / agent.state=idle。`agent.version` 仍缓存 v0.7.20（无害）。
- 结论：**面板"更新"按钮在本版 updater 下不可用**（除非先手动 pull latest）；升级一律走脚本。DEVELOPMENT.md 已写明。

## 让 cli2api 面板更新真正可用（三件套）
- 目标：用户不必每次找我，面板「立即更新」要能用。
- 关键缺口：updater 拉 `repo:vX.Y.Z` 但 compose 用 `repo:latest` 重建，本地 latest 不动 → 必回滚。
- 方案：新增 systemd 常驻 `cli2api-image-sync.service`，每 3 秒把 `:latest` 对齐到本地最新版本 tag（读 `org.opencontainers.image.version` label 比较，**只前进不降级**）。
  - 实测：把 latest 指回 v0.7.25，6 秒内自动回到 v0.7.26，日志 `tagged ... latest -> v0.7.26 (version v0.7.26, was v0.7.25)`。
  - **不要用 docker events**：`docker pull` 已存在的镜像不产生任何 pull 事件（实测事件流为空），只能轮询。内存占用 ~600KB。
- 新增 `cli2api-updater-watchdog.timer`（每 5 分钟）：status.json 处于 checking/downloading/installing/rolling_back 且 started_at 超过 15 分钟 → 重启 updater 并清 status，解决昨晚卡 13.7 小时那类无超时卡死。
- 三件套：cli2api-updater.service（官方更新器）+ cli2api-image-sync.service（latest 对齐）+ cli2api-updater-watchdog.timer（防卡死），全部 active。
- 备选脚本：/opt/scripts/update-cli2api.sh（pull + 对齐 + 重建 + 校验 + 失败回滚）。
- DEVELOPMENT.md 已把「面板不可用」改为「面板可用 + 三件套说明」。
- 时序：updater pull 完约 10 秒才重建，3 秒轮询来得及。
