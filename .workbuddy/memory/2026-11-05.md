## 18:00-21:00 把 asxs 流量切到 c2a（用户确认接受模型降级）
- 需求：峰段 1.00x 太贵，把该时段所有走 asxs 上游的请求转到 c2a(渠道36)。用户明确确认接受模型降级：`gpt-6.1-sol` 在渠道27是真实 GPT-6.1-Sol，在渠道36映射到 `deepseek-v4.1-flash`。
- 容量评估：workbuddy 剩余 11841 credits / 16 账号，近 3 天 18-21 时段 c2a 仅 1 次 429，够用。
- 实现（不禁用渠道，避免影响 asxs-gpt56-direct 分组及 budget guard 自动启用）：按时段改 **priority**。
  New API 用 `ORDER BY priority DESC`（大的优先），故 18-21 把渠道36 的 priority 1→20（超过 27 的 10），27 保留为 fallback。
- 脚本 `/opt/scripts/cmsg_peak_shift.py on|off|auto|status`：
  **必须同时改 `channels.priority` 和 `abilities.priority`**（缓存由 abilities 构建）；渠道缓存 `SyncChannelCache` 每 60s 同步（SYNC_FREQUENCY=60）。
  `auto` 按北京时间 hour 判断 18<=h<21 → on，否则 off。
- 定时：systemd `cmsg-peak-shift.timer`，`OnCalendar=*-*-* *:00/5:00` 每 5 分钟自检，边界精确（18:00/21:00 都落在 :00）且重启自愈（Persistent + OnBootSec）。
- 验证：临时 on → 等 70s 缓存同步 → token 4 连发 3 次全部走 channel 36 ✅；随后 off 恢复 priority=1。
- 一键回滚：`sudo python3 /opt/scripts/cmsg_peak_shift.py off` 并停掉 timer。
- ⚠️ 计费说明：切到 36 后按 c2a 价格（$0.137/M）且**不叠加渠道27的峰谷倍率**（group_ratio=1），比 1.00x 的 asxs 便宜约 15 倍。公告里 18-21=1.00x 那条对该时段实际流量已不适用，如需应补公告说明。
- 公告 id=7 追加说明：「18:00 ~ 21:00 高峰时段，请求会自动调度至 c2a 通道，按该通道价格计费，不适用上表的 1.00x 倍率」。
  同样需 `PUT /api/option/` 同步内存；DB 与 `/api/status` 都已核对（content len=319，含说明）。id/publishDate 不变，保持置顶。
